## 3. 验证机制抓到的问题

### 3.1 隐藏后轮盘仍然可见（已修复）

`--overlay-probe` 报出「控制器认为可见=否，但 `IsWindowVisible` 查询=是」。

根因：`PlaceAtCursor` 用 `SetWindowPos(..., SWP_SHOWWINDOW)` 绕过 WPF 直接显示了窗口，WPF 内部仍认为它是隐藏的，于是后续的 `Hide()` 成了空操作。

修复：可见性一律由 WPF 的 `Show()`/`Hide()` 控制，`SetWindowPos` 只负责位置与尺寸，去掉 `SWP_SHOWWINDOW`。

**这个 bug 值得记下来** —— 它是"用 Win32 查询结果去核对，而不是相信自己的状态变量"这个做法直接换来的。如果只依赖 `overlay.IsVisible`，它会一路潜伏到用户抱怨"轮盘关不掉"。

### 3.2 遮罩是灰纱而不是黑纱 + 点击关闭完全未生效（已修复）

由用户反馈「全屏遮罩颜色要用半透明黑色」触发排查，发现两个同源缺陷：

**症状一：遮罩是一层灰纱。** 遮罩窗口复用了系统预定义的 `STATIC` 窗口类，它的背景画刷是
「按钮表面色」（浅灰）。`LWA_ALPHA` 只给这个灰色加透明度，于是得到灰纱而非黑纱。

**症状二：点击空白处关闭完全没生效。** `CreateWindowEx` 使用系统预定义类时
**不会使用我们提供的窗口过程** —— 我写了 `Proc` 却从来没有把它装上去，
于是 `WM_LBUTTONDOWN` 处理和 `WM_MOUSEACTIVATE` 都形同虚设。

**修复**：注册自己的窗口类（`WinQuick.DimMask`），带上
`hbrBackground = BLACK_BRUSH` 与真正的 `lpfnWndProc`。

**新增的自动验证（关键）**：`--overlay-probe` 现在会
1. 沿屏幕中部横线找最亮的像素并记录原始颜色
2. 显示遮罩后再读同一像素，比较各通道的变暗比例
3. 判据：纯黑 + 统一 alpha 时各通道比例应一致且约等于 `1 - alpha/255`

实测：`RGB(43,43,43)` → `RGB(26,26,26)`，三个通道比例均为 **0.605**（期望 0.6），
**通道间差异为 0**。若底色仍是灰色画刷，暗通道会被抬高、比例必然失衡 —— 这是唯一能
自动区分「黑纱」与「灰纱」的办法。

点击关闭则通过向遮罩投递 `WM_LBUTTONDOWN` 并核对窗口真实可见性来验证。

> **教训**：我在 M1 初稿里把「遮罩点击关闭」列为已实现，但从未验证过它 ——
> 它其实一次都没工作过。功能列进"已实现"表格不等于被验证过，
> 这两件事必须在文档里分开写。

### 3.3 显示器真实参数被纠正

真实显示是 **3072×1920 @ 168 DPI（175% 缩放）**，而不是最初用 DPI-unaware 进程读到的 1755×1097 @ 100%。详见 [M0-findings.md §1](M0-findings.md)。

## 4. 只有人才能做的验证

我无法按热键、也无法看到界面，以下必须在真机上由人确认：

### 4.1 热键唤出（最重要）

```
src/WinQuick.App/bin/Release/net10.0-windows/WinQuick.exe
```

启动后托盘出现图标，按 **Ctrl+Win+W**：

- [ ] 轮盘是否出现，且**感知延迟是否够快**（目标 <100ms）
- [ ] 全屏是否有一层变暗遮罩，且变暗程度是否合适（当前 40% 黑）
- [ ] 圆盘是否以光标为中心；把光标移到屏幕角落再按，圆盘是否被整体钳制在屏内
- [ ] **12 点方向是否是一个完整扇区**（而不是一条缝）—— 这是 M0 修掉的几何缺陷，值得亲眼确认
- [ ] 鼠标划过扇区是否高亮、离开是否恢复
- [ ] 点中心 / 按 Esc / 点圆盘外，三种方式是否都能关闭
- [ ] 关闭后，焦点是否回到你切换之前正在用的那个窗口

### 4.2 不按热键直接看视觉效果

```
WinQuick.Probes.exe --overlay-probe --hold=30
```

直接显示轮盘并保持 30 秒（Esc 可关闭），用于纯粹看外观。改完视觉参数后重复这条命令即可快速迭代。

### 4.3 视觉审美

当前是**占位视觉**：深灰扇区、`#0078D4` 悬停高亮、白色标签、中心显示 "Esc"。
外圈那层半径 350 的半透明黑底盘已按反馈移除 —— 实测观感是一圈多余的灰色圆盘；
需要的层次感优先用扇区描边与悬停高亮表达，而不是加大面积底色。

它能验证几何、配色、透明这些可量化部分是否成立，但好不好看需要你的判断。

> **一个遗留的内存杠杆**：环 2 目前在 r=[206,350]，窗口边长因此定为 740。
> 底盘移除后窗口内有大片空白区域（可见内容只到 r=200）。
> 若 M2 定稿后环 2 的外径能收窄到 300，窗口可缩到 620² 左右，约省 5MB。
> 窗口面积和内存成正比，这是几何设计时值得一并考虑的约束。

M2 会先做视觉规格定稿。我可以按不同风格渲染几版 PNG 给你挑，但**我无法评价"好不好看"** —— 这条判断必须由你做。
