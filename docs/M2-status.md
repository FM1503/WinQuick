## 2. 动画的两个刻意设计

**退场不阻塞动作执行。** 退场动画只决定"什么时候看不见"，不参与"什么时候执行"。
用户按下扇区后，动作立刻发生、焦点立刻归还，动画只是视觉收尾。
Kando 的 #650 就是因为在退场淡出之后才启动应用、让用户感到延迟而被抱怨。

**尊重系统的「显示动画」开关。** `SystemParameters.ClientAreaAnimation` 为关时所有时长归零。
无障碍偏好不是可选项。

曲线用 `SplineDoubleKeyFrame` + `KeySpline` 实现，而不是 `DoubleAnimation` + `EasingFunction` ——
WPF 内置的 `CubicEase` 是固定曲线，要精确复现 `cubic-bezier(0,0,0,1)` 只能走 KeySpline。

## 3. 图标验证：两条独立路径互相印证

**应用内报告**：`成功取到图标的项 7 / 8`（第 8 项是刻意留空用于验证占位图的"开发工具"）。

**PNG 像素级验证**：`analyze-render.ps1` 按扇区中心角采样图标区域的最大饱和度。
判据是**饱和度而不是灰度**——shell 图标是彩色的，占位图是灰度圆加文字，
纯扇区填充是无彩深灰。三者在灰度上几乎无法区分，靠肉眼看小图很容易漏掉。

```
扇区 0  中心   0°  最大饱和度 100%  -> 彩色（真图标）
扇区 1  中心  45°  最大饱和度  27%  -> 彩色（真图标）
...
扇区 7  中心 315°  最大饱和度   0%  -> 无彩色（占位或无内容）
彩色扇区 7 / 8
```

两个数字一致，说明图标是真的渲染到了像素上，而不是只存在于对象模型里。

## 4. 规格护栏抓到的两个问题

把设计决策写成断言之后，立刻暴露了两处我自己的错误：

**其一：死区比例低于我声称的规范。** 死区原为 52，占外径 `52/350 = 14.86%`，
**低于 Don Hopkins 建议的 15% 下限**。而我在 M0 文档里写着"符合 15-25% 规范" —— 那是错的。
已调为 56（16%），并更正了 M0 文档。

**其二：示例菜单的图标路径错了三处。** 见 §5。

护栏里现在锁住的约束包括：窗口边长不得超过内存预算反推的 740、死区比例落在 15%-25%、
环必须严格外嵌、外环放得进窗口、图标与文字半径不得碰撞、
入场曲线必须精确等于 `cubic-bezier(0,0,0,1)` 且时长为 167ms、
悬停延迟落在 150-300ms 区间且收起延迟必须大于展开延迟。

## 5. 实测发现的 UWP 缺口（M3 必须处理）

内置示例菜单最初 3 项取不到图标，逐项排查后：

| 项 | 原路径 | 实际情况 |
|---|---|---|
| 资源管理器 | `System32\explorer.exe` | **路径错误**，它在 `%WINDIR%` 根目录 |
| 设置 | `System32\SystemSettings.exe` | **文件不存在**，Win11 的「设置」是 UWP 应用 |
| 画图 | `System32\mspaint.exe` | **文件不存在**，Win11 的「画图」已是商店应用 |

前一条是我的 bug。后两条是真发现：

> **Win11 上「用户想启动的应用」里有相当一部分是 UWP / 商店应用。**
> 它们既不能用文件路径取图标，也不能用文件路径启动，
> 需要走 shell 的 AppsFolder / AppUserModelId（`shell:AppsFolder\<AUMID>`）。

这会同时影响 **图标提取** 和 **动作执行** 两条链路。M3 做动作执行器时必须处理，
否则用户会发现"设置、计算器、画图这些加不进菜单"。现在的应对是先探测文件是否存在、
不存在就退化为首字占位。

### 建议你做的验证

```
src\WinQuick.App\bin\Release\net10.0-windows\WinQuick.exe
```

按 **Ctrl+Win+W**，重点看：

- **图标是否清晰**（不是糊的、不是通用占位图标）
- **入场动画的节奏**：167ms 从 90% 放大到位，是否"感觉不到延迟"又"不是硬切"
- **退场是否顺滑**，以及按下扇区后是否**立刻**切回原窗口（不该等动画）
- 图标与文字在扇区里的位置是否协调（图标偏内 r=102、文字偏外 r=168）

不按热键直接看：`WinQuick.Probes.exe --overlay-probe --hold=30`
