## 1. 先说结论

**伪 3D 在 WPF + 分层窗口上只有三条便宜的路**，其余要么贵、要么会牺牲文字清晰度：

| 路 | 做法 | 依据 |
|---|---|---|
| **光影与描边** | 一片斜光 + 棱边高光 + 接触阴影 | Fluent 2 的 Elevation：用阴影与光表达远近；**Windows 一侧明确用描边而不是重投影表达轮廓** |
| **层次与视差** | 环 / 图标 / 文字三层以不同速率到位 | Microsoft Learn 的 Parallax：近的比远的动得快 |
| **按"距离"逐项缩放与淡出** | 用角度的余弦当"进深"，逐项给缩放/透明度/层序 | iOS 滚轮（把选项排在虚拟圆柱面上）的成熟配方 |

**真透视（`Matrix3DProjection`）只在入场那一瞬间能用**：WPF 会把挂了投影的元素先渲染进一张
**中间纹理**再透视重采样，这会**关掉 ClearType 子像素抗锯齿 —— 文字会发虚**；而中间纹理本身还有
逐帧代价（这类中间表面多了，WPF 会退到软件渲染，那是 WPF 掉帧最常见的原因）。
所以规矩是：**入场期间挂投影，落定前必须清掉**，静止态永远是纯 2D。

## 2. 调研（含出处）

### 2.1 官方：深度是怎么表达的

- **Fluent 2 · Elevation**：Elevation 是"物体与它背后表面之间的**可感知距离**"，靠**阴影与光**表达；
  界面的层次感是把组件放在 z 轴的不同高度上。**阴影方向**传达一个一致的光源，**阴影大小**表示远近
  （小而锐＝近，大而软＝远）；官方给了 6 档阴影 token（`$shadow2/4/8/16/28/64`）对应卡片、提示、
  对话框等。**平台差异**：Windows 一侧**用描边而不是主阴影**来表达轮廓。
  → 这解释了为什么我们现有的一套（半透明底 + 细描边）本身就是 Windows 的"正确做法"，
  也说明"加深度"在 Windows 语汇里首选**光与棱边**，而不是堆阴影。
  出处：[Fluent 2 · Elevation](https://fluent2.microsoft.design/elevation)、
  [Windows 应用设计准则](https://learn.microsoft.com/windows/apps/design/guidelines-overview)。
- **Microsoft Learn · Parallax**：定义是"**离观察者近的元素比背景元素移动得快**"，由此产生深度、
  透视与运动感；UWP 有专门的 `ParallaxView` 控件（`Source` 前台、`Child` 背景、`VerticalShift`/
  `HorizontalShift` 控制速率差）。官方的注意事项里明确写着**不要到处用 —— 滥用会削弱它的效果**。
  出处：[Microsoft Learn · Parallax](https://learn.microsoft.com/windows/apps/design/motion/parallax)。

### 2.2 成熟配方：伪 3D 的"距离感"怎么算

- **iOS 滚轮（UIPickerView 的鼓形）**：把选项排在**虚拟圆柱面**上，容器 `rotateX` 转动，
  每一项按它到中心的距离给 **缩放（有下限，如 0.2）、透明度、zPosition 层序、阴影半径**；
  位置用三角函数（`sin` 垂直位置、`cos` 做透视缩短），半径由"每项弧长"反推；
  `cameraDistance` 控制透视强度（越小＝广角、越夸张）。
  → 这一档是"**不碰透视、只靠距离函数**"就能读出立体感的证据：我们把它搬到圆盘上就是
  "近的那几格更大更亮、远的那几格更小更暗"。
  出处：[纯 JS 的 iOS datepicker（rotateX + 圆柱）](https://codepen.io/gnauhca/pen/JrdpZZ)、
  [RN 里重建 iOS 滚轮（scale/opacity 插值）](https://stackoverflow.com/questions/52504054/how-to-rebuild-the-ios-picker-animation-in-react-native)、
  [Jetpack Compose WheelPicker（投影数学）](https://jishuzhan.net/article/2090998029670039553)。
- **游戏武器轮盘**：GTA 风格轮盘普遍把 3D 做成一个**开关**（ScaleformUI 的 `RadialMenu` 有
  `Enable3D` 属性）；Unity 的那些轮盘资源普遍带**厚度层**与"旋转/扇形展开"动画。
  → 说明"伪 3D 可以按档位开关"是被产品验证过的做法，也说明"厚盘"是轮盘这一品类的常见语汇。
  出处：[ScaleformUI · RadialMenu（Enable3D）](https://manups4e.github.io/ScaleformUI/RadialMenu/)、
  [Procedural Radial Wheel Menu（Unity）](https://assetstore.unity.com/packages/templates/systems/procedural-radial-wheel-menu-310471)、
  [Framer · 3D Circular Menu（相机倾斜/半径）](https://www.framer.com/community/marketplace/components/3d-circular-menu/)。

### 2.3 WPF 的两条硬约束（决定可行性）

1. **投影会让文字发虚**：`Matrix3DProjection` 把元素渲进中间纹理再做透视重采样，ClearType
   子像素抗锯齿被关掉；社区对这类模糊的建议是像素对齐、`UseLayoutRounding`/`SnapsToDevicePixels`，
   但**根因是重采样本身**，只能靠"别长期挂着投影"来规避。
2. **中间渲染表面（IRT）有逐帧代价**：DrawingBrush/VisualBrush/透明度遮罩/TileBrush 都会产生 IRT，
   数量一多就掉帧，甚至退回软件渲染 —— 而本工具的窗口是**分层窗口**，每一帧本来就要付一次
   整窗回读（见 M0/M6/M8 的代价模型）。
   出处（技术约束两条）：WPF 渲染与 Perforator/IRT 的说明、WPF 高 DPI 下文字模糊的分析
   （搜索未回传可点击链接，故按"可复现的公开分析"记录）。

## 3. 六档候选

原型：`preview/depth-preview.html`（六档各配一段专属入场；画廊静止对比 + 大舞台逐个播放）。

| 候选 | 深度来源 | 专属入场 | 悬停 | 成本 | 风险 |
|---|---|---|---|---|---|
| **① 现状（平面）** | 无（基线） | 缩放 .86→1／300ms 过冲 + 旋转 -24°→0／380ms + 淡入 167ms | 只换颜色 | 零 | 零 |
| **② 表面光影** | 光影（Fluent Elevation） | 缩放 .94→1／300ms；**光在盘面到位之后才亮起**（420ms，延迟 90ms） | 底色加亮 6% + 棱边高光 | 低（静态渐变 + 两条棱边环带 + 一个阴影椭圆） | 低（不动逐帧预算、不碰文字） |
| **③ 厚度挤出** | 实体厚度（侧壁 + 落地阴影） | 从上方 46px **落下**到 0／340ms；**阴影随高度收放**（越高越小越淡） | 把这一格**按下去** 4px | 低（12 个额外路径，静态） | 中（侧壁是"假"的：各项颜色不同时接缝会露出来） |
| **④ 逐项深度（转盘感）** | 按距离逐项缩放/淡出（余弦进深） | 逐项淡入／260ms、相位差 25ms，同时把深度从 0.4 推到 1 | 被悬停那格**往观察者方向来**（额外 1.08 倍） | 低（每项一个矩阵变换，逐帧只改 12 个矩阵） | 低（纯变换、文字不重采样；但"近大远小"会让最下方那格略大） |
| **⑤ 真透视倾斜（入场专用）** | 矩阵透视（`Matrix3DProjection`） | 透视从 62° 立到 0°（perspective 900px）／380ms | 与现状相同（只改入场） | 中-高（倾斜期间每帧整窗透视重采样） | **高（倾斜期间文字会发虚）** |
| **⑥ 层间视差** | 层次与视差 | 环 .88→1、图标 .93→1（延迟 40ms）、文字 .96→1（延迟 70ms） | 图标挪 6px、文字挪 3px（"浮在扇区上方"） | 低（三条变换动画） | 低（含蓄；官方也提醒别滥用） |

**组合建议**：**② 光影 + ④ 逐项深度**最稳（前者给"面"，后者给"体"）；**② + ⑥ 视差**更含蓄；
**⑤ 与任何一档都能叠**，因为它是入场专用、结束即清除。

## 4. 要实现的话，落在哪（技术映射）

| 候选 | 实现位置与做法 |
|---|---|
| ② 光影 | `RadialRingVisual.Build`：加三条**静态**图形 —— 整圈渐变带（一片斜光）、两条棱边环带（外缘亮、内缘淡）、一个径向渐变阴影椭圆（放在环后面）。全部用冻结画刷，进逐帧预算的只有"悬停时改两条描边的透明度" |
| ③ 厚度 | 侧壁 = 整圈环带向下偏移 N px 的深色路径（画在环层**下面**）；落地阴影与"高度→阴影"是逐帧只改透明度/缩放的动画（这一档的深度线索几乎免费） |
| ④ 逐项深度 | 每项一个 `MatrixTransform`（**同一个实例**同时给扇区、图标、文字 —— 它们在同一个坐标系里，所以同一矩阵可直接复用），逐帧只改 12 个矩阵；深度函数 `depthOf(angle) = (1 - cos θ)/2` 是纯函数，可单测 |
| ⑤ 真透视 | 根内容元素挂 `Matrix3DProjection`，参数就是 `tokens.json` 里那对**至今没人读的** `perspective` 令牌（`entranceTiltDegrees` / `entranceDepth`）；**落定前把 `Projection` 置空** |
| ⑥ 视差 | 三个图层各挂一条变换动画（环 / 图标 / 文字）—— 与现有 `TransformGroup` 的入场通道同一套机制，只是分成三层 |

**注意"一个机制一个写入者"**：④ 的悬停放大必须乘在它自己的深度缩放上，不能直接写 `scale(1.08)`
（那会把按角度算出的 0.94~1.06 抹掉）；这一条在原型里已经踩过一次（同一元素两条动画互相覆盖）。

## 6. 待你定的

1. **要哪一档**（可组合；我推荐 ②+④，或只做 ②）。
2. **③ 厚度的"按下去"手感**要不要（另一种是"抬起来"，更像常规高亮）。
3. **④ 的"近大远小"幅度**：现在是 0.94~1.06（最下方那格比最上方大 12%）。
   要不要更含蓄（0.97~1.03）或更夸张（0.90~1.10）。
4. **⑤ 真透视要不要做**。它的观感我无法在原型里给你（HTML 不糊），
   而且它的成本必须**在真机上量**（倾斜期间每帧整窗透视重采样）。
   如果要做，我会先量一次再决定时长/角度。

## 7. 未做 / 已知风险

- **真透视的成本与文字清晰度**：只能真机实测。做法建议是先加一个 `--depth-probe`（离屏逐帧渲染
  + 帧间隔统计），量过再决定。这条**不做测量就实现是不负责任的**，所以放在第 4 问里等你点头。
- **厚度与"子环"的关系**：子环（220–350）现在是一段弧；给它加厚度/光影要不要跟着做，属于
  选定候选之后的第二步（与 M8 里"形态与子环"是同一类问题）。
- **图标本身的立体化**（给图标底板、投影、内阴影）没做：那涉及图标像素处理（一次性缓存），
  是另一条独立的路（见 M8 §11.3 的"图标待遇"）。

## 8. 第二轮：v1 判定为「没有 3D 的感觉」→ v2 改轮廓（含布局修正）

用户反馈两条：**「效果都不行，没有 3D 的感觉」**、**「选项列表和预览区应该左右布局」**。

### 8.1 为什么 v1 看着平（我的复盘）

v1 的六档**全都是「一个平面圆盘 + 加点光影」**：轮廓始终是正圆，只是加了斜光、棱边、
接触阴影、逐项缩放（幅度只有 ±6%）、以及一条**入场才出现**的透视。

**假 3D 的第一性判据是轮廓**：人眼判断"这东西立着还是躺着"，靠的是**外形的压扁**
（圆 → 椭圆）与**近大远小**，光和影只是修饰。v1 一档都没改轮廓，所以怎么加光都还是平的
—— 这不是参数没调好，是**换错了树**（与 §AGENTS.md 3.5 里"参数微调 vs 换一棵树"同一个教训）。

### 8.2 v2 的六档（全部改轮廓）

| 候选 | 轮廓 | 立体线索 | 入场 | 成本 |
|---|---|---|---|---|
| ① 现状（平视） | 圆（452×452） | 无（基线） | 缩放+旋转（现状） | 零 |
| ② 斜盘 35° | **椭圆 0.82** | 压扁 + 近大远小 16% + 侧壁 10px | 盘面"立起来"（1.0→0.82，340ms） | 低 |
| ③ 斜盘 52° + 厚盘 | **椭圆 0.65** | 压扁 + 近大远小 28% + 侧壁 18px | 立起来（→0.62，360ms） | 低 |
| ④ 透视斜盘 | **椭圆 0.70 + 近端更宽** | 压扁 + **半径随进深变化**（近 ×1.12 / 远 ×0.88）+ 高光带 | 立起来 + 高光在到位后亮起 | 低 |
| ⑤ 立牌环 | **椭圆轨道 0.64 + 直立卡片** | 每项是一块竖牌（顶面高光 + 侧面） | 牌子从平面"长起来"（相位差 28ms） | 中 |
| ⑥ 真透视（整体 rotateX 42°） | 透视（含文字倾斜） | 对应实现里的 Matrix3DProjection | rotateX 58°→0° | 中-高（字会发虚） |

**几何做法**：盘面上的点 = `(r·sinθ, -r·cosθ·squash)`，半径再按进深乘一个系数
（`gain`：正交为 0，透视味为正值）。扇区路径 = 两条**椭圆弧** + 两条直线；
整圈环带用外顺内逆的双子路径（非零环绕出洞）。**命中测试的逆映射是闭式的**：
给定点先算 θ → 该角度的进深 → 反算"有效半径"范围再比较，不需要迭代。

**关键取舍**：v2 里除了 ⑥，**文字一律保持直立、只按进深缩放** —— 立体感来自
「斜盘 + 直立项」的对比，而这条路线**不重采样文字、不发虚**，也不动逐帧预算
（除倾斜那 340ms 是逐帧改几何，而 12 个扇区的几何重建实测 0 掉帧）。

### 8.3 布局修正（并固化）

原型改成**左列选项 + 右列预览**（左右并排，同屏可见），左列每项带一个**只画轮廓**的小缩略图
—— 挑形态/立体感时差异主要就在轮廓上，缩略图一眼能比。这条已写进 `AGENTS.md` §3.5。

### 8.4 验证（`preview/_verify.mjs`，页内自检 **6/6**）

- 六档几何都落在 740×740 内且非空；
- **轮廓真的是椭圆**：平视档 高/宽 = 1.00，倾斜档 0.82 / 0.65 / 0.70 / 0.64
  （这条断言就是为 v1 那种"全是正圆"准备的 —— 它现在能红）；
- 进深函数 12 点最远、6 点最近且单调（0.00 / 0.50 / 1.00）；
- **近大远小落到几何上**：6 点图标半径 9.72 > 12 点 8.28；
- 层序：阴影 → 侧壁 → 环 → 高光 → 图标文字 → 中心（写反会盖住东西）；
- 每档入场都有动画产出、位移类悬停也有动画（按 `hoverKind` 分类核对）。

顺带修了自检器一个"工具本身的问题"：它原来写死 `#gallery .card` 选择器，
布局一改就数出 0 张卡片（读数成了假象）——现在按 `.card` 数，与布局无关。

## 9. 第三轮：改用 SAO（刀剑神域）那套全息语言

用户反馈：**「效果都不对，你可以参考 SAO-UI（刀剑神域风格 UI）的 3D 效果」**。
这是换语言，不是再调参数 —— 前两版的失败同一个根源：我在"几何投影"上打转，
而 SAO 的"3D 感"来自**一整套视觉语言**。

### 9.1 调研：SAO 的 UI 是怎么构成的（含出处）

- **SAO Utils**（GPBeta 做的 Windows 桌面启动器，就是"完全潜行 3D 应用启动器"）：
  Alpha 2（2013）加入**循环菜单**（项目多于 5 个时自动转成环形，可视范围随项目数自适应）与首个 3D 启动动画；
  **Beta 1（2015）正式引入 3D 菜单界面**，并带主题系统（SAO/GGO）。也就是说
  "环形菜单 + 3D + 浮动"在这类工具里是**有产品先例**的。
  出处：[SAO Utils 官网](http://www.gpbeta.com/)（Steam 上也有 SAO Utils 2: Progressive）。
- **网页复刻们的技术手法**（可直接搬的"招"）：
  · `transform: perspective() rotateX()/rotateY()` 把平面立起来；
  · `clip-path: polygon(...)` **切出梯形/斜角面板** —— 这是 SAO 面板最认得出来的特征；
  · 青色 `box-shadow` + 伪元素**四角标**做边框；
  · 半透明底 + 玻璃感；`keyframes` 做**脉冲发光与浮动**。
  出处：[SAO UI Plan: SAO Utils WEB 2.0](https://cloud.tencent.cn/developer/article/1834116)、
  [Card Widget（rotateX 梯形标签）](https://cloud.tencent.com.cn/developer/article/1856665)、
  [WarrenUhrich/SAO-UI](https://github.com/WarrenUhrich/SAO-UI)、
  [grzhan/SAOUtilsHTML5](https://github.com/grzhan/SAOUtilsHTML5)。
- 另外几个 SAO 复刻的共识：**分层深度 + 鼠标视差 + 克制的发光**，并用 `clip-path` 做斜角
  （见 Personal Reality 那类项目的做法总结）。

### 9.2 照着我们的渲染预算翻译成 WPF 能做的

| SAO 手法 | 在原版里 | 我们的做法 |
|---|---|---|
| 平面立起来 | `perspective + rotateX` | **按视角直接画几何**（椭圆 + 进深），文字保持直立 → 不发虚、不重采样 |
| 切角面板 | `clip-path: polygon()` | 路径里把弧线两端内缩 + 直边连接（多边形路径本来就是最便宜的几何） |
| 青色发光边框 | `box-shadow` 叠加 | **垫一条更粗更淡的描边**（Effect/模糊在分层窗口上逐帧代价太大，本项目实测过） |
| 半透明玻璃面 | `backdrop-filter: blur` | 半透明填充（**真模糊不可得**，见 M8 §2.3），层次靠"线与面"的对比 |
| 浮动 / 扫描光 | keyframes | 变换动画与旋转渐变光弧；**但常驻浮动 = 每帧都在重合成**，所以默认只做入场 |

## 11. 第五轮：**每格独立的 3D**（不是整个轮盘）

用户：**「我要的是每个扇区独立的 3D 效果，不是整个轮盘」**。
§10 那一版是"整块盘面一起躺下"（一个共享平面），而用户要的是**每格自己是一个立体对象**。

### 11.1 做法：每格 = 一块自己的平面板，绕自己的切向轴取姿态

把每一格当成一块**独立的板**，它的四个角落在**这一格自己的投影**里：

```
屏幕点 = 锚点(该格中径处) + v·切向 + u·cosφ·径向 + (0, u·sinφ)
        u = 径向偏移（px，正=向外）  v = 切向偏移（px，正=顺时针）
        φ = 这一格绕**自身切向轴**的倾角（φ>0 外缘下沉，φ<0 外缘翘起）
```

于是：**厚度** = 同一块板向屏幕下方偏移的一份深色副本（带顶缘高光），**阴影** = 再偏一点的一份
（硬边，不做模糊 —— 模糊在 WPF 里逐帧太贵）。三者叠起来，"这一块是立体的"就成立，
而且**每格互不共享**：一格的姿态变了，其余七格一动不动。

### 11.2 实测抓出来的一个几何事实（值得记）

"外缘翘起"**不是** φ 取负就能做到的：在 6 点方向，"径向"本来就朝下，
φ=-34° 时的上抬量（80px）抵不过径向下沉（119px）—— 量出来外缘仍比内缘**低 39px**。
要做到"翘起"必须 **|φ| > 45°**（tanφ > 1）。这条是自检按"声明的意图 + 真实几何"核对时暴露的：
我原本给 ④ 写的是 φ=-34°，量出来和 ③ 只是幅度不同、并没有换一种姿态。改成 **φ=-58°** 后
量到外缘比内缘高 46px，才真的成了"向上张开的花"。

### 11.3 六档（`preview/sao-preview.html`）

入场**六档相同**（与现状逐参数一致，有自检钉着）。差别只在每格的姿态：

| 候选 | 每格的姿态 | 量出来的证据 |
|---|---|---|
| ① 现状（对照） | 整块平面 | — |
| ② **每格独立厚板** | φ=0 + 厚度 11px（8 块各自有侧壁与阴影） | 面/侧壁/阴影各 8 条，路径互不相同 |
| ③ **每格外倾** | φ=+34°（外缘下沉） | 6 点那格：内缘 y=398 → 外缘 y=598（Δ=+200px） |
| ④ **每格内倾** | φ=-58°（外缘翘起） | 内缘 y=521 → 外缘 y=475（Δ=-46px） |
| ⑤ 高低错落 | φ=+16° + 相邻格高度交替 12px | — |
| ⑥ **悬停立起** | 静止薄板；悬停那一格 φ→-62° | 外缘相对内缘从 -144px 抬到 -195px；**只有 1 格几何变化** |

### 11.4 悬停这一版动了（要说清）

②③④⑤ 悬停时**那一格抬起 12px**，⑥ 悬停时**那一格绕自身轴立起到 -62°** ——
这是"每格独立"最直接的表达，也是这一轮唯一与现状不同的交互反馈。若不要，说一声即可去掉。

### 11.5 验证（页内自检 **9/9**，无脚本错误）

- 六档入场参数与现状完全一致（本轮要求，会失败）；
- ② 八块板各自有独立路径（8+8+8 条，且互不相同）；
- ③④ 的外缘高度**按声明的意图**核对（用真实几何量，不看代码）；
- ⑥ 的"立起"确实把外缘抬起来；⑥ 悬停时**只有 1 格**几何发生变化（"独立"的回归锁）；
- 六档几何都在 740×740 内；层序（阴影→侧壁→面→图标→文字→中心）正确；每档入场产出三条通道。

### 11.6 还没定

- 选哪一档；②的厚度（11px）、③④ 的 φ（34°/58°）、⑤ 的错落幅度是否合适。
- **子环（第二层，220–350）**要不要按同一套"每格独立"来做 —— 原型仍只画一级环。
- 每格倾斜后**标签可读性**：③ 外缘下沉 200px 会把最下方那格的文字压到窗口下缘附近，
  真机上要复核。

## 12. 第六轮：先上网补课，再换成「六种材质」

用户：**「不好看，换一批，不要闭门造车，先去网上学习成熟好看的案例」**。
复盘：前面几轮我一直在**自己发明几何**（椭圆、切角、光柱），而"好看"来自**材质怎么叠**，
那是别人已经沉淀好的东西。

### 12.1 学到的三条（含出处）

1. **「深度永远不是一个投影」** —— 一块元素看起来是实体，靠的是**四层叠在同一个元素上**：
   ① 渐变主体；② 斜面/内发光的 inset；③ 悬停时渐入的亮层（"像灯亮起来"）；
   ④ **顶部一条柔和的镜面高光**。这份技法清单按"技法而不是颜色"分了十种材质：
   Glossy / Glow / Metal / Foil / Layered / Inset / Glass / Neon / Duotone / Satin，
   并强调"一套结构，换变量就是另一种材质"——**这正是"皮肤"应该有的结构**。
   出处：[The Art of Color Depth](https://21st.dev/@arlanoska/components/color-depth/metal)。
2. **visionOS（Apple 官方）**：玻璃材质靠**镜面高光与阴影**传达"窗口在空间里多远、多大"；
   没有明暗模式，材质自己适应背景；文字要比 iOS **更粗**一档才稳。
   出处：[Design for spatial user interfaces（WWDC23）](https://developer.apple.com/videos/play/wwdc2023/10076)、
   visionOS HIG（另：Liquid Glass / WWDC25 是同一路的延续）。
3. **成熟的径向菜单几何是"梯形分割"**：每格外宽内窄、缝隙清晰、大圆角；那类 CSS 3D 径向菜单
   用 `perspective + rotateY(-77.5°)` 把每格做成圆柱面上的板、悬停才放大。
   **但 77.5° 会让侧面的格子窄到读不出来**，所以这里只取了它的**形状语言**（梯形 + 大圆角 + 缝隙），
   倾角收在 6–14°。
   出处：[Radial / Circular Menu Concept（CodePen）](https://codepen.io/lenymo/pen/rwmBGq)、
   [Rams Radial Menu（3D 径向菜单的完整实现，含 reduced-motion）](https://nuwudmultimedia.com/behind-the-scenes-of-the-rams-radial-menu-build/)、
   [Obscura（Dribbble，径向菜单的层级叠加）](https://dribbble.com/shots/22920226-Obscura)。

### 12.2 六种材质（`preview/sao-preview.html`）

一套结构（每格四层 + 描边），换变量就是另一种材质：

| 材质 | 四层怎么叠 | 悬停 |
|---|---|---|
| ① **黏土 Clay** | 渐变主体 + 内上亮下暗 + 顶部镜面高光 + 外侧柔和投影（大圆角 26） | 抬起 12px，投影随之变大变浓 |
| ② **玻璃 visionOS** | 半透明主体 + 亮色渐变描边（上缘最亮）+ 顶部内发光 + 柔和投影 | 抬起 10px + 边框亮一档 |
| ③ **高光拟物 Glossy** | 竖向渐变 + **硬边镜面高光带**（上半）+ 底部内阴影 + 投影 | 抬起 11px + 高光带更亮 |
| ④ **软 UI Neumorphism** | **同色挤出**：左上外亮影 + 右下外暗影 + 内缘反向一对 | **被按下去**（内外阴影对调，不是位移） |
| ⑤ **金属 Metal** | 多段渐变（拉丝高光）+ 亮棱线 + 面板间暗缝 + 投影 | 抬起 10px + 亮棱线换段 |
| ⑥ **霓虹玻璃 Neon** | 暗玻璃 + 霓虹描边（多层描边造发光）+ 顶部镜面高光 + 投影 | 抬起 13px + 描边加亮 |

### 12.3 两条方法论判据（都进了自检）

- **「每格都是四层叠加」**：上一批"不好看"的根因就是**每格只有一层平涂**。
  自检里逐材质核对四层 + 描边是否都在（`clay:4层+描边 … neon:4层+描边`）。
- **「光照方向全盘一致」**：所有格子共用**同一支**"左上亮→右下暗"的渐变描边
  （自检核对描边取值种类必须 = 1）。每格各自打光会立刻显脏，这是"看着专业"与"看着业余"的分界。

### 12.4 诚实的差距

- **柔和阴影**是用"径向渐变的影子块"做的，不是模糊 —— WPF 里逐帧模糊代价太大（本项目实测过）。
- **玻璃做不了真折射/真模糊**（分层窗口拿不到系统材质），所以是"玻璃的样子"，与 visionOS 的差距是物理性的。
- 软 UI 那档的对比度天然低（这是该材质的固有属性），文字靠 2.4px 深色描边 + 纯白保证可读。

### 12.5 验证

页内自检 **7/7**、无脚本错误：入场与现状逐参数一致；每格四层 + 描边；光照全盘一致；
每格倾斜落到几何（6 点那格内缘 y=410 → 外缘 y=588）；六档几何都在窗内；悬停只改一格；入场产出三条通道。

## 13. 第七轮：形状被剪切了 —— 找到根因并重做（形状不动，立体靠"五件事"）

用户：**「扇区形状怎么都扭曲了，而且 3D 感不强，重新设计」**。

### 13.1 根因：我的"倾斜"是多算了一项

上一轮我给每格做的投影是 `u·cosφ·径向 + (0, u·sinφ)`。**正交投影下，一块板绕自身切向轴倾斜
只应产生"径向缩短"（`u·cosφ`），不该有屏幕内的位移** —— 我额外加的 `(0, u·sinφ)` 竖直下沉，
对 **3 点/9 点方向**的格子就成了"沿着不是它法线的方向平移"，于是每块都变成剪切过的四边形。
**这是数学错误，不是审美问题。** 这一版把所有变形去掉：扇区就是扇形。

### 13.2 立体感不强的原因：只有一层，没有"落点"

上一版每格只有薄薄一层，没有厚度、没有底座、没有投影落点。成熟做法（§12.1 的第一条）说得很清楚：
**深度不是一个投影，而是几层叠出来**。所以这一版把立体拆成**五件事**：

| # | 层 | 作用 |
|---|---|---|
| ① | **侧壁** | 同形同尺寸的面板向屏幕下方偏 10–20px 的深色副本 —— 厚度从这儿来 |
| ② | **底座托盘** | 一圈比扇区略大的暗色环，扇区"放在"它上面（有托盘才有"离桌面多高"） |
| ③ | **落影** | 每块自己的投影落在托盘上，**悬停时随抬起变大变浓** |
| ④ | **斜面高光** | 同一支"左上亮→右下暗"的渐变描边（光照全盘一致） |
