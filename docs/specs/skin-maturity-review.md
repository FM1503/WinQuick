# 皮肤功能行业评审：从「能用」到「正式」的差距与路线（2026-11-21）

> 评审对象：M8 换肤（七套皮肤 × 形态 × 动效档、TokenStore 合并模型、SkinPanel）。
> 方法：现状盘点（代码+M8 文档）对照行业基准（M8 §2 既有调研 + 2026-11 增量：Win11 官方色彩规范）。
> 结论先行：**架构层已是行业正道（令牌合并模型主流、即换即用优于同类、动效随肤有 M3 官方背书）；差距全部在完成度与质感层**，共 8 项，分三级路线。

## 一、行业基准（要点与出处）

| 维度 | 行业标准 | WinQuick 现状 | 判定 |
|---|---|---|---|
| 主题模型 | 令牌化+分层覆盖（@gregogun CSS 变量同模型；Kando theme.json） | tokens.json + 皮肤局部覆盖 + 合并校验 | ✔ 正道 |
| 生效方式 | Kando 换主题需重启（其 issue #1253 还在要皮肤内预设） | 即换即用、面板真令牌预览 | ✔ 领先 |
| 动效随肤 | M3 Expressive motion scheme 官方先例；硬规矩：过冲只给位移、颜色/透明度通道恒临界阻尼、系统「减少动画」优先 | 皮肤带动效档已实现 | ✔ 有背书，但个别档违规（见 D4） |
| 全应用一致 | 主题作用于应用全部界面（VS Code/Raycast/Kando 均如此） | **只换轮盘，设置/皮肤面板不跟随** | ✘ D2 |
| 系统联动 | Win11 官方：应用默认跟随用户 light/dark 与强调色（"Color is personal"，learn.microsoft.com/windows/apps/design/signature-experiences/color，2026-10 版） | 无跟随 | ✘ D3 |
| 可扩展 | Kando：用户主题目录（theme.json+preview.jpg+社区仓库） | 仅内置 7 套 | ✘ D5 |
| 宣称=实际 | — | 宣称 4 形态实有 2（饼/圆角/花瓣/刻度盘 ✔；卡片弧/网格未做）；perspective 令牌无代码读取 | ✘ D1 |

## 二、差距清单（「半成品/粗糙」的八个具体来源）

- **D1 死键与档案债**：`perspective` 令牌至今无代码读取（M8 §10.5.2）；「形态宣称 4 实有 2」经复核**不成立**——pie/rounded/petal/dial 四形态均已实现，卡片弧/网格仅为 M8 §11.2 候选调研、从未在 UI 宣称（本评审初稿误报，如实更正）。
- **D2 界面割裂（粗糙感最大来源）**：换肤只作用于轮盘，设置面板/皮肤面板永远一张脸（M8 §8.7 建议过「跟随，只换材质不换布局」，未做）。
- **D3 无系统联动**：不跟随 Win11 明暗模式与系统强调色——2026 年桌面工具默认预期。
- **D4 动效档越线**：⑤明显过冲、⑦阶梯（M8 §8.2 自己标记待定）违反 M3「过冲只给位移」红线；观感即「糙」。
- **D5 无用户皮肤**：不能放自己的皮肤文件（§8.4）；无覆盖冲突规则（§8.5：用户 accentColor vs 皮肤色谁赢未定义）。
- **D6 验证盲区**：皮肤面板无探针（§10.5.5），切肤闪不闪没有量化锁。
- **D7 打磨散点**：皮肤面板密度档原型（skinpanel-preview 三档）挑了未接线；七套皮肤质量参差（留哪几套 §8.1 未裁）。
- **D8 浅色皮肤内容显示问题（用户 2026-11-21 实报）**：浅色皮肤令牌本身自洽（#F3F3F3 底 + #1B1B1B 字），但界面存在**硬编码色值**（控件/面板代码与 XAML 中写死的深色块与白色边，如队列行 #2A2F3A、遮罩白边等），浅色令牌下错乱；且皮肤校验只查 hoverFill↔hoverLabel 一对（DesignTokens.cs:88-96），label↔sectorFill、角标文字↔badgeFill 等关键配对无对比度约束。行业依据：Fluent 官方铁律「use theme brushes rather than hard code color values」+「test in both light and dark themes to ensure legibility」（learn.microsoft.com/windows/apps/develop/ui/theming，2026-02 版）。

## 三、路线（三级，供讨论）

**P0 · 达到「正式」底线**（不做完不该叫正式功能）
1. D2 设置/皮肤面板跟随换肤（只换材质不换布局——Install 重写资源即生效的机制已具备）；
2. D4 动效档按 M3 规矩收紧（过冲只给位移通道；⑤⑦ 重调或删除）；
3. D1 还债：删除（或显式标注预留）perspective 死键令牌，消除「令牌存在但无行为」的档案债。
4. D8 全量令牌化：清除界面硬编码色（改语义令牌，明暗随皮肤自动适配）+ DesignTokens.Validate 补全对比度配对（label↔sectorFill、hint↔sectorFill、badge 文字↔badgeFill 等），并加「皮肤×明暗全组合可读性」探针校验。

**P1 · 行业对标**
4. D3 跟随系统明暗+强调色（新增「跟随系统」作为第八套动态皮肤：监听 UISettings/注册表，映射到令牌层）；
5. D5 用户皮肤目录（Kando 模式：skins.d/ 下 JSON + 面板扫描；覆盖规则=用户覆盖>皮肤>基线，冲突时面板提示）。

**P2 · 差异化（可选）**
6. 卡片弧/网格形态（新命中测试+分形态校验）；2.5D 倾斜入场；霓虹档粒子火花（M6 预研在案）。
